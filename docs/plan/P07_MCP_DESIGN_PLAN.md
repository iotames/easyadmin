# P07 设计计划：MCP 能力目录与智能体装配协议

> 状态：`PROPOSED`（2026-11-26 初稿）。本文件只冻结不随实现细节漂移的决策；**定稿前必须刷新第 2 节现状结论并重新送审**。未批准、未开工。

## 1. 背景与目标

### 1.1 目的（Objective）

让智能体在 EasyAdmin 上开发时，先发现并复用框架已有能力，再生成最小必要代码；把“一站式开箱即用”与“按能力解耦接入”统一为可查询、可校验的装配模型，减少重复造轮子。

### 1.2 目标（Goals）

- 能力可发现：覆盖后端基础设施、内核契约、内置应用、前端组件与数据访问能力，并给出“禁止自建”的标准替代入口。
- 契约可查询：API、页面、配置、模块与数据契约可被机器读取。
- 装配可生成：按接入 profile 生成业务薄壳与组合根（生成能力依赖 P05）。
- 结果可校验：架构、契约、构建与验收可被 MCP 触发。

### 1.3 策略（Strategies）

- **单一事实来源**：能力目录由编译期显式注册表提供，禁止手写第二份清单；条目指向真实符号并由测试守护。
- **生成同源**：MCP 不实现独立模板或生成器，复用 P05 的脚手架核心。
- **只读优先、写有边界**：发现与校验默认只读；写操作限定业务工作区，框架仓库默认只读。
- **分期交付**：先只读能力，再生成，再升级与替换。

### 1.4 度量（Measures）

- 目录条目与真实导入路径、入口符号一致率 100%（自动化测试）。
- 高频需求场景检索命中率 100%（场景清单在定稿时固定）。
- 解耦 profile 产物的依赖集符合该 profile 声明（构建产物断言）。
- 违规注入（裸 fetch、自建日志/会话/审计/任务、直接 `sql.Open`）全部被架构检查捕获。
- 生成产物一次构建与测试通过。

| 资产 | 当前事实 | 对本期含义 |
|---|---|---|
| 组合根 | `cmd/easyadmin` 是唯一能同时看见全部模块的位置，内置模块清单由组合根统一提供 | 生成与校验必须复用组合根口径，测试不得复制清单 |
| 模块契约 | `kernel/module` 定义 Manifest、Declare、Register、生命周期 | 能力目录需描述模块接入方式，而不是重定义契约 |
| 基础设施 | `infra` 已交付 conf/logx/db/httpapi/apperror/auth/audit/tasks/scheduler/credential 等独立门面；`storage` 属 P04 未交付 | 目录覆盖已交付能力及其“禁止自建”替代关系，并为 P04 交付项预留追加位 |
| 内置应用 | `apps/system`（用户、角色、权限、审计、配置只读）、`apps/console`（仪表盘） | 目录需标注内置应用可关闭、可替换的边界 |
| 前端 | `webui/assets/core`（api/notify/router/layout/menu 等）与 `components` 公共组件 | 目录需覆盖组件与页面契约，阻止页面裸 fetch 与自造组件 |
| 契约文档 | `docs/API.md`、`docs/CONVENTIONS.md`、`docs/DATA_DICT.md`、`docs/FRONTEND.md` | 契约查询应以这些正式文档为来源，不另写一份 |
| 接入方式 | README 2.2 是单一 Hello World 目标用法，尚无按能力组合的系统化接入 | 本期补 profile 化接入模型 |
| 脚手架 | P05 尚未交付，生成器不存在 | 生成类能力必须等待 P05，不可在 MCP 内另起一套 |
| MCP | 当前无 MCP 服务端、无能力目录 | 本期全部为新增 |

## 3. 本期范围

- 能力目录注册表与一致性测试。
- MCP 服务端（stdio）与只读工具：能力发现、契约查询、架构与契约校验。
- 生成类工具：按 profile 生成组合根与模块骨架，复用 P05 脚手架核心。
- 升级与替换计划工具：输出影响面与步骤，不自动改业务代码。
- 接入 profile：`full`、`api-only`、`worker`、`custom`。
- 使用说明与能力目录维护指南。

本期不新增业务功能，不改变现有运行时行为。

## 4. 明确不做

- 远程模块市场、在线代码下载、Go `.so` 插件加载。
- 运行期目录扫描或反射注册。
- 自动编写业务逻辑、低代码建表或拖拽页面生成。
- 让 MCP 修改框架源码。
- 把 MCP 作为框架运行时依赖；框架启动不依赖 MCP。

## 5. 架构与契约决策（初稿冻结）

### 5.1 部署形态

MCP 作为单二进制子命令运行，使用标准输入输出传输，离线可用，不引入 Node 或 Python 运行时。远程共享传输属于独立议题，需单独评审，不在本期默认交付。

### 5.2 能力目录单一来源

能力目录由编译期显式注册表提供。每个条目至少表达：唯一标识、类别、导入入口、依赖集合、是否可脱离一站式方案独立使用、可替换实现、对应的“禁止自建”替代关系、守护测试。具体包位置与字段命名在定稿时确定；**条目不得由另一份手写清单生成，也不得在 MCP 内复制**。

### 5.3 生成能力与 P05 同源

脚手架与模板只有一个实现，MCP 仅做协议适配：参数校验、能力检索、调用生成核心、返回结果。若 P05 尚未交付，MCP 只交付只读能力，不得临时实现生成器。

### 5.4 接入 profile

- `full`：默认一站式，含前端与内置系统模块。
- `api-only`：只装配 HTTP API 与数据访问。
- `worker`：只装配任务、调度、日志与数据访问，不监听 HTTP。
- `custom`：按能力标识列表组合，生成器按依赖拓扑排序。

profile 的准确性由构建产物依赖集断言守护，不靠文档声明。

### 5.5 写操作边界

- 写工具只允许写显式指定的业务工作区；框架仓库默认只读，需显式开关才可写。
- 不覆盖已存在文件；强制覆盖必须同时提供备份路径。
- 只执行白名单命令（构建、测试、静态检查、框架自检）。
- 扫描排除版本库、依赖目录、临时目录与敏感配置；输出脱敏。

### 5.6 分期

- M1：能力目录与只读工具（发现、契约、校验）。不依赖 P05，可先行。
- M2：生成类工具，与 P05 同源。
- M3：升级与替换计划工具。

## 6. 交付与影响面

- 组合根新增 MCP 子命令。
- 新增能力目录注册表与一致性测试。
- 与 P05 共用的脚手架核心边界需要预留。
- 新增 MCP 使用与工具契约文档。
- P06 发布资产需包含 MCP 版本信息与协议版本。

## 7. 验收标准

- 能力目录与真实符号一致性测试通过，注入失效条目会被捕获。
- 场景检索命中：任务、审计、登录、表格、上传、定时、配置、页面、权限、错误码均命中标准能力并给出复用建议。
- `api-only` 与 `worker` 生成产物的依赖集符合 profile 声明；`full` 产物可启动登录。
- 架构检查对注入的裸 fetch、自建日志/会话/审计/任务、直接 `sql.Open` 全部报错，恢复后转绿。
- 写工具越界路径与无备份覆盖被拒绝。
- 协议层具备初始化、工具枚举、工具调用的自动化测试。
- 端到端记录：通过 MCP 完成一次业务模块生成，生成后构建、测试与页面加载通过。

## 8. 数据与持久化边界

本期不新增数据库表。能力目录是编译期常量，MCP 无状态，不读写运行数据库。若未来需要调用统计，必须单独设计，默认关闭、仅本地存储、不外发。

## 9. 质量自评

| 维度 | 自评结论 | 评审重点 |
|---|---|---|
| 工程化最佳实践 | 目录单一来源、生成同源、边界可测 | 是否真的没有第二份清单 |
| 用户体验 | 智能体先查后写，接入从单例变为 profile 组合 | 工具是否足够少而通用 |
| 改动量与复杂度 | 只读层可独立交付，生成层复用 P05 | 是否把生成逻辑塞进 MCP |
| 架构统一性 | 与显式装配、单一入口原则一致 | 是否引入运行期扫描或隐式注册 |

## 10. 风险与缓解

- **目录与代码漂移**：以符号存在性测试守护；定稿前强制刷新现状结论。
- **生成器双实现**：与 P05 共用核心，MCP 不持有模板。
- **智能体绕过 MCP**：以架构检查兜底，并在智能体工作规则中要求先检索能力。
- **工具权限过大**：工作区白名单、默认只读、覆盖需备份。
- **P05 延期**：M1 可独立先行，M2 等待。
- **协议演进**：固定协议版本并保留兼容测试。
