# P06 实施计划：稳定与正式发行

> 本文件是 DESIGN_PLAN 的实施指导，不单独送审；按设计定稿后的实际代码基线校准，实施仍需独立开工授权。

## 1. 实施前检查

- [ ] 本期 DESIGN_PLAN 已由用户明确确认并标记 APPROVED。
- [ ] 前置阶段 P05 已 ACCEPTED，遗留问题已核验。
- [ ] 用户已另行明确授权本期开工。
- [ ] 当前仓库代码、目录、依赖版本和测试入口已重新检查。
- [ ] 本期 API/配置/数据/权限/菜单/页面契约影响已列明。
- [ ] 任何超出设计边界的发现已先提交决策，不擅自扩大范围。

## 2. 实施步骤

1. 审核所有公共包、接口、错误码、API、模块 Manifest 和 Provider 契约。
2. 制定 semantic version、弃用窗口、兼容性和数据迁移政策。
3. 完成数据库升级、备份、恢复和失败恢复演练。
4. 建立 HTTP/DB/Task/WebUI 基准，并设置回归阈值。
5. 执行安全测试：会话、CSRF、RBAC、上传、敏感数据、依赖漏洞。
6. 构建目标平台发行包，加入版本/commit/build time 和许可证清单。
7. 选取至少两个真实业务项目进行接入和升级演练。
8. 汇总问题、修复、更新文档并冻结 v1.0 发布候选。

## 3. 主要修改文件/目录

- `docs/COMPATIBILITY.md`、`docs/UPGRADE.md`、CHANGELOG。
- CI release workflows、build metadata、SBOM/license 输出。
- 性能/安全测试基准和报告。
- 示例业务项目和结构升级演练记录。

实际文件以实施前仓库核对为准；如与此计划不同，先更新计划并记录原因。

## 4. 测试与验收执行

兼容性测试、结构升级/恢复 e2e、性能 benchmark、安全测试、跨平台构建、真实项目验收。
回退：发布候选可撤回；数据库升级须有备份与经演练的恢复流程；API 不做破坏性变更，无法兼容时新增独立端点并走重大决策。

- [ ] `gofmt`、`go test ./...`、`go vet ./...` 通过。
- [ ] 适用的 race、集成、浏览器或跨平台测试通过。
- [ ] 失败用例和边界情况有证据，不以“本地可运行”代替验收。

## 5. 文档同步清单

- [ ] README / AGENTS（使用方式或长期工程规则变化时）。
- [ ] ARCHITECTURE / DECISIONS / ROADMAP（架构、决策、阶段变更时）。
- [ ] API / 配置 / 数据字典 / 日志专题文档（契约变化时）。
- [ ] COMPONENTS / FRONTEND / PROJECT_STRUCTURE（模块、组件或目录变化时）。
- [ ] 示例、模板和浏览器验收记录（如适用）。

## 6. 风险控制与回退

- 不以通过编译代替行为兼容。
- 破坏性数据库变更必须备份、演练和恢复说明。
- 未完成测试的数据库/平台不列为正式支持。
- 多实例限制在文档、doctor 和启动诊断中清楚呈现。

每一项涉及持久化数据的步骤必须明确备份、恢复和失败状态；不得把不可逆结构变更描述为可自动回滚。
