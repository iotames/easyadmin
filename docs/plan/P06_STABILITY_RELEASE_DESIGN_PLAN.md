# P06 设计计划：稳定与正式发行

> 状态：`PROPOSED`（待用户评审；未批准前不得进入本期实施）。

## 1. 背景与目标

将 EasyAdmin 从可用原型推进到可被多个业务项目长期依赖的 v1.0。

## 2. 本期范围

P06 以已发布版本和既有数据结构为兼容对象；除为修复具体缺陷且经过独立结构升级评审外，不预设新增核心业务表。所有数据结构兼容规则以结构同步和升级验证为准。

- 公开 API/Module/Provider 契约与兼容策略。
- 结构同步、数据迁移、备份恢复和升级测试。
- 性能基准与安全基线。
- 依赖升级/弃用/数据迁移流程。
- 跨平台发行、构建信息、许可证和供应链清单。
- 至少两个真实项目试用反馈。

## 3. 明确不做

- 未经专门设计的多实例/多租户。
- 为追求功能数量引入大型基础设施。
- 破坏性 API/数据升级无升级工具直接发布。

## 4. 架构与契约决策

- 明确哪些包/API 属公开稳定面。
- 兼容性与废弃策略。
- 数据迁移/备份/恢复。
- 安全与性能 SLO/基准阈值。
- 发布物可复现。

设计必须服从 `docs/ARCHITECTURE.md`、`docs/DECISIONS.md` 和 `docs/CONVENTIONS.md`。若本期需要改变其中任一正式边界，必须先提交 ADR/决策修订，不可在实施计划中暗改。

## 5. 交付与影响面

- `docs/COMPATIBILITY.md`、`docs/UPGRADE.md`、CHANGELOG。
- CI release workflows、build metadata、SBOM/license 输出。
- 性能/安全测试基准和报告。
- 示例业务项目和结构升级演练记录。

## 6. 验收标准

- 升级演练可从前一稳定版本完成。
- 公开 API 有向下兼容测试：旧版请求/响应 fixture 通过，字段只增不改。
- 关键性能基准可复现。
- 安全检查清单逐项有测试/证据。
- 两个真实业务项目无需修改内核源码即可接入。

每项验收都必须对应可执行测试、命令、浏览器操作或源码核验记录。截图不能替代功能测试。

## 7. 数据与持久化边界

本期默认不增加核心表。任何确需的数据结构演进必须先明确旧版本结构升级路径、备份/恢复策略和兼容窗口，并将其列为独立设计决策；不得把数据结构变更塞进发布整理。

## 8. 风险与缓解

- 不以通过编译代替行为兼容。
- 破坏性数据库变更必须备份、演练和恢复说明。
- 未完成测试的数据库/平台不列为正式支持。
- 多实例限制在文档、doctor 和启动诊断中清楚呈现。

## 9. 前置条件

- 前置阶段为 P05；只有 P05 完成终验并标记 ACCEPTED 后，本期才可开工。
- 本期 DESIGN_PLAN 先由用户明确确认；IMPL_PLAN 在设计确认后按当时仓库代码校准，不是设计评审前置条件。
- 用户另行明确授权本期实施后，才建立 TODO/STEP 并进入实施。
- 外部依赖和易库版本以本期实施前实测为准；未知语义必须有验证步骤。
