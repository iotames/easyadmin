# P00 设计计划：地基与工程规范

> 状态：`PROPOSED`（待用户评审；未批准前不得进入本期实施）。

## 1. 背景与目标

目标是定稿架构和工程基线，建立可复现仓库与最小构建反馈环。

## 2. 本期范围

- 文档、决策和目标目录基线。
- Go/easy 系列版本及 local development 接入方案核验。
- Go build/test/vet CI 与依赖方向架构测试骨架。
- WebUI dev 磁盘模式和生产 embed 骨架。
- 最小 App/页面 smoke 验证，不包含真实业务数据和认证。

## 3. 明确不做

- 用户管理、RBAC、业务数据表和完整后台页面。
- 任务/调度、CLI 代码生成和 Provider 生态。
- 未经确认引入 ORM、Vue/React 或 Node 构建链。

## 4. 架构与契约决策

- 组合根和分层依赖图固定。
- easy 系列依赖版本固定策略和升级策略。
- `go:embed`/`-tags dev` 双模式契约。
- AGENTS 与七期计划治理流程。

设计必须服从 `docs/ARCHITECTURE.md`、`docs/DECISIONS.md` 和 `docs/CONVENTIONS.md`。若本期需要改变其中任一正式边界，必须先提交 ADR/决策修订，不可在实施计划中暗改。

## 5. 交付与影响面

- `go.mod`、工作区接入文件、CI workflow、Makefile（可选）。
- `cmd/easyadmin/` 最小入口、`kernel/` 最小 App。
- `webui/embed*.go`、最小 `index.html`。
- `docs/`、`AGENTS.md` 和架构测试目录。

## 6. 验收标准

- 文档之间无死链和互相矛盾。
- 干净环境可执行 go build、go test、go vet。
- dev 模式可读磁盘资源，生产模式 embed 资源完整。
- 架构测试能捕获故意违规依赖/裸 fetch/底层库绕行。
- easy 系列未知语义登记为后续核验项。

每项验收都必须对应可执行测试、命令、浏览器操作或源码核验记录。截图不能替代功能测试。

## 7. 风险与缓解

- 不执行核心表迁移，不创建真实管理员。
- 不把 easy 系列调用方推断当作底层库保证。
- 依赖版本不明确时阻止进入 P1。

## 8. 前置条件

- 前置阶段已验收，记录可查。
- 本期 DESIGN_PLAN 已由用户明确确认。
- IMPL_PLAN 已根据当前仓库代码校准文件路径和接口。
- 外部依赖和易库版本已固定；未知语义已列出验证步骤。
