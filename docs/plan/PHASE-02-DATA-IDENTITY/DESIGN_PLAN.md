# P02 设计计划：数据与身份安全

> 状态：`PROPOSED`（待用户评审；未批准前不得进入本期实施）。

## 1. 背景与目标

提供真实持久化、首次管理员初始化、会话、RBAC 和审计。

## 2. 本期范围

- infra/db、命名数据源、SQL loader、事务、超时和慢查询。
- SQLite 默认库、版本迁移、checksum 和方言脚本。
- 用户/角色/权限/会话表，认证、CSRF、登录限流、首次初始化。
- RBAC 和 Audit Service。
- 用户、角色、认证、权限、初始化与审计 API。

## 3. 明确不做

- OIDC/LDAP、OAuth Server、多租户和分布式会话。
- 任务中心/调度和文件管理。
- 未通过测试认证的数据库方言支持承诺。

## 4. 架构与契约决策

- SQL-first、int64 主键、UTC 时间和统一数据字典。
- 只实现启动配置；Runtime Settings 明确后置，不在本期造空接口。
- 服务端会话和 CSRF 安全模型。
- 迁移自动执行策略与失败恢复。
- RBAC 权限码和 Manifest 同步。

设计必须服从 `docs/ARCHITECTURE.md`、`docs/DECISIONS.md` 和 `docs/CONVENTIONS.md`。若本期需要改变其中任一正式边界，必须先提交 ADR/决策修订，不可在实施计划中暗改。

## 5. 交付与影响面

- `infra/db`、`infra/auth`、`infra/audit`。
- `sql/{sqlite,mysql,postgres}/` 和模块迁移资源。
- 用户/角色/认证/初始化/审计模块 API。
- `docs/DATA_DICT.md`、`API.md`、`CONFIGURATION_DESIGN.md`。

## 6. 验收标准

- 空 SQLite 环境可初始化核心表和管理员。
- 登录、登出、会话撤销、CSRF、登录限流和改密行为通过测试。
- API 401/403/409/422 语义正确。
- 最后一个超级管理员不能被禁用/移除。
- 迁移重复执行、checksum 不匹配和失败恢复有测试。
- PG/MySQL 只按完成的真实矩阵标注支持。

每项验收都必须对应可执行测试、命令、浏览器操作或源码核验记录。截图不能替代功能测试。

## 7. 风险与缓解

- 不把 Register 当迁移执行器。
- 不在普通配置查询中返回秘密原文。
- 不允许删除最后一个活跃超级管理员。
- 方言支持状态必须和测试证据一致。
