# 配置系统设计

> 本文定义 EasyAdmin 对配置的逻辑契约；easyconf 的具体函数签名、优先级和并发保证必须以 P1 锁定版本实测。

## 1. 目标与唯一入口

`infra/conf` 是应用配置唯一入口，底层适配 `easyconf`。业务模块不直接读取环境变量、文件或命令行。配置项显式注册、类型明确、来源可追踪、敏感值可脱敏、热更行为可测试。

## 2. 两类权威来源

### 2.1 Bootstrap Config

监听地址、数据目录、主 DSN、日志目标、Cookie 密钥引用、部署环境等进程级设置。由 easyconf 适配层加载，通常在启动阶段确定。

### 2.2 Runtime Settings（后续能力，v0.x 不落地）

v0.x 只实现 Bootstrap Config。站点名称、默认分页、可在线调整的模块行为、通知开关等运行期数据，作为后续的 Settings Service 能力预留；真正落地时必须同时补齐：

- `sys_setting` 或等价持久化表；
- 权限、版本冲突校验、审计和更新事件；
- 明确的读取优先级与缓存失效策略；
- 对应 API、前端页面和测试。

禁止在本期用“以后再说”的 Runtime Settings 概念掩盖配置来源。更禁止让数据库运行设置隐式覆盖监听地址、主 DSN、TLS 私钥等部署配置。若未来需要数据库覆盖某个 bootstrap key，必须作为单独 ADR/决策列出优先级。

## 3. 注册模型

每个模块在 `Declare` 阶段显式注册配置项，字段至少包括：

| 字段 | 含义 |
|---|---|
| key | 全局唯一键，具有模块命名空间 |
| module_id | 所属模块 |
| type | string/bool/int/int64/number/duration/list/JSON 等明确类型 |
| default | 类型匹配默认值 |
| title / description | 面向管理员与开发者的用途说明 |
| source_class | bootstrap 或 runtime |
| sensitive | 是否敏感，普通读取不得回显明文 |
| required | 是否必填 |
| hot_reload | hot / restart / immutable |
| validator | 显式校验规则 |
| writable | 管理 UI 是否允许修改 |
| persist_policy | 修改如何持久化，或不可持久化 |

注册阶段校验重复 key、非法默认值、缺说明、模块归属错误和热更策略矛盾。不得以反射扫描结构体 tag 生成配置项。

## 4. 加载顺序与来源追踪

目标来源优先级建议：显式命令行 > 进程环境变量 > 指定配置文件 > 自动生成默认值快照 > 代码默认值。但**只有在 easyconf 对应版本确认支持并通过测试后，才可将其写成正式优先级**。

配置快照应记录：有效值、来源类型、是否使用默认值、是否需要重启、最近变更版本。不能只显示当前值而隐藏其来源。

`default.env` 若采用，应由注册表生成，不手工编辑；它是默认快照，不是第二套配置系统。

## 5. 热更新协议

热更级别：

- `hot`：运行时能安全切换，必须经过验证和原子快照发布；
- `restart`：在线修改只能进入待应用状态或通过受控配置文件持久化，需重启；
- `immutable`：运行期禁止修改。

热更顺序：接收候选值 → 类型/字段/跨项校验 → 相关消费者 Prepare → 发布新快照 → 发变更事件 → 收集结果；无法安全回滚的设置不得标记 hot。

Watch 回调不得在底层配置锁持有期间执行；回调不可重入导致死锁。该行为需针对 easyconf 实测。

## 6. 持久化和 `.env` 写回边界

`.env` 写回只适用于明确由该文件管理且应用目录可写的部署方式。以下情况不能将写回 `.env` 宣称为持久化成功：

- 当前有效值来自进程环境变量或命令行，优先级高于 `.env`；
- 容器/只读文件系统由部署系统管理配置；
- 文件权限、原子替换或并发更新不满足要求；
- 若后续启用 Runtime Settings，属于运行设置的数据存数据库，不塞进配置文件；v0.x 不提供该入口。

管理 UI 修改配置必须返回 `applied`、`persisted`、`restart_required`、`source` 等明确状态。非阻断持久化失败可以返回成功加 warning，但必须如实说明重启后的行为。

## 7. 敏感配置

普通查询只返回 configured/masked 状态，不返回原文。秘密写入需要权限、审计和安全存储；日志和审计不得包含秘密。生产密钥优先由部署系统注入或密钥管理设施提供，不写仓库和默认配置快照。

## 8. 管理 UI

管理页面根据注册表生成分组、标题、类型、默认值、来源、热更和重启信息。只允许编辑 `runtime` 或显式 `writable` 且可持久化的字段。密钥输入不回填原文；更新需要版本号/乐观锁避免覆盖并发修改。

## 9. easyconf 核验清单

P1 必须针对锁定版本核验：注册 API、重复 key 语义、默认值生成、优先级、文件监听、Watch 并发、Set 持久化、错误返回、关闭行为。无法满足的能力要么在适配层补足，要么提交 easyconf 扩展设计；不允许业务模块绕开 `infra/conf`。
