# EasyAdmin 七期建设路线图

> 状态：P00、P01、P02 已实施、验收并归档（2026-11-26）；P03 已实施并完成验收（2026-11-26，待归档）；P04-P06 未批准、未开工。每期在计划目录根部配对 `<项目>_DESIGN_PLAN.md` 与 `<项目>_IMPL_PLAN.md`，已完成项目归档到 `docs/done/`。计划治理以 `docs/plan/README.md` 为唯一权威。

## 1. 总体策略

采用纵向切片推进：每期结束都有可构建、可启动、可操作、可回归的结果。先验证地基，再建立最小闭环；先让框架自身的后台使用公共能力，再扩大扩展生态。

**阶段规则**：

1. 先冻结阶段设计，再授权实施；设计批准不等于自动开工。
2. 每期明确“做什么、不做什么、验收什么”；不跨期偷跑。
3. 新抽象必须说明不增加会导致什么具体问题。
4. 内置后台是框架第一个消费者；不为它开绕过统一入口的后门。
5. 当前单实例优先；不以进程内锁伪装多实例安全。
6. 每期都同步 API、配置、数据、菜单、权限、测试和正式文档。

## 3. P0：地基与工程规范（v0.0）

### 目标

基于现有 `infra/` 代码核验架构、依赖和目录边界，修正文档与工程入口，再补齐尚不存在的最小运行骨架和开发反馈环。P0 设计须先获用户确认，实施须另获明确开工授权。

### 交付

- 完成 README、AGENTS、ARCHITECTURE、DECISIONS、ROADMAP、COMPONENTS、CONVENTIONS、FRONTEND、API、DATA_DICT、CONFIGURATION、LOGGING 等文档定稿。
- 固化公共组件统一设计约定（职责、依赖注入、配置、Context、生命周期、错误、并发、观测、测试和适配边界），不创建强制万能接口。
- 明确 HTTP 输入解析、字段级校验和领域规则的职责分层；独立校验包是否成立留待 P1 基于真实 DTO 验证。
- 建立 `cmd/`、`kernel/`、`infra/`、`apps/`、`webui/`、`sql/`、`docs/` 等目标目录。
- 确认 easy 系列本地开发接入方式：子模块、workspace 或 replace 策略；固定版本来源和升级方法。
- 核对 Go 最低版本和直接依赖准入清单。
- 建立 Go 构建、单测、vet、race 的基础 CI；前端浏览器测试面骨架。
- 建立 `go:embed` 生产模式和 `-tags dev` 磁盘读取模式骨架。
- 建立依赖方向与禁止入口的架构测试；故意违规样例必须被检测出来。
- 最小运行入口和最小页面，只证明构建、静态资源和 HTTP 生命周期接通；不提前建设业务表和登录。

### 验收

- 干净环境可构建、测试、vet；版本和依赖可复现。
- 开发模式修改静态资源后刷新可见；生产构建资源完整内嵌。
- 架构测试能识别反向依赖、底层库绕行和前端禁用模式。
- 文档链接、计划配对和目标目录一致。
- 公共组件的设计约定可用于评审现有和新增组件，且没有制造统一万能接口。
- 请求解析、字段级校验与领域规则各有明确归属；422 字段错误契约与 API 文档一致。
- easy 系列的未确认行为均被记录为验证项，而不是假设。

### 不做

用户管理、数据库业务表、登录、RBAC、完整布局、任务中心和 CLI 生成器。

## 4. P1：运行时内核（v0.1-alpha）

### 目标

形成可解释的 App 和模块生命周期，让开发者能用一个最小模块注册配置、路由和元信息。

### 交付

- `kernel.App`、Module/Manifest 契约、依赖图、重复 ID/路由冲突/循环依赖校验。
- 两阶段 `Declare` / `Register`；可选 Lifecycle Start/Stop；启动失败清理和逆序关闭。
- infra 的 easyconf/easyserver/easyserver-log 适配；配置类型化注册、快照和受控 Watch。
- Logger 门面、稳定业务错误、统一 HTTP 路由/响应/RequestID/Recover/AccessLog。
- 请求结构解析与字段级校验的统一实现；字段错误按 422 契约返回，具体校验包以 P1 评估结论为准。
- `/api/meta`、`/healthz`、`/readyz`。
- 优雅停机和资源关闭顺序。

### 验收

- 最小模块完整注册并出现在 meta；禁用模块不注册运行资源。
- 重复 ID、缺依赖、循环依赖、路由冲突在监听前失败并准确定位。
- HTTP 中间件顺序有集成测试；panic 有 request_id 和统一错误响应。
- 配置优先级、Watch 并发和 Server shutdown 行为通过真实 easy 库适配测试。
- 启动部分失败后已启动资源得到清理。

### 不做

业务数据表、登录、RBAC、任务中心和完整 WebUI。

## 5. P2：数据与身份安全（v0.1-beta）

### 目标

打通真实持久化、首次管理员初始化和服务端授权，使后台具备安全承载业务数据的基础。

### 交付

- 以现有 `infra/db`、`DataSourceManager` 为起点核验命名数据源、SQL 脚本加载、参数绑定、事务、连接池、慢查询和超时；复用已存在能力，不按空白重写。
- 默认 SQLite 初始化；PostgreSQL/MySQL 适配与方言测试，按实际结果分级支持。
- 声明式结构同步：`TableSpec` 清单 + 幂等 Ensure；`DiffSchema` 只读差异预览，变更 SQL 必须显式确认；不建版本迁移账本。
- 用户、角色、权限、会话和关联表；bcrypt 等成熟密码哈希；Cookie 会话、CSRF、登录限流。
- 一次性首次管理员初始化流程；最后一个超级管理员保护。
- RBAC 路由授权与菜单权限元信息；服务端是最终权威。
- 独立 Audit Service 与核心危险操作审计。
- 用户、角色、认证、初始化、权限、审计 API。

### 验收

- 删除默认 SQLite 文件后首次启动，自动完成核心表创建并进入安全初始化。
- 未登录 401、无权限 403、CSRF 失败 403、字段校验 422；不能绕过服务端检查。
- 用户禁用、密码修改和权限调整的会话失效行为有测试。
- 最后一个活跃超级管理员不可被禁用/移除。
- 结构同步重复执行安全；失败不会伪装成功；方言支持矩阵有真实 CI 证据。
- Audit Log 与 Application Log 分离，敏感字段不泄露。

### 不做

OIDC/LDAP、多租户、分布式会话、复杂策略引擎和外部 API Token 平台。

## 6. P3：WebUI 管理台（v0.1）

### 目标

提供真正可操作的开箱即用中后台，并证明统一组件和模块契约能承载业务开发。

### 交付

- 原生 ESM 前端内核：boot、router、layout、menu、api、notify、theme、store、perm、format、dom。
- 全局布局插槽、菜单树、面包屑、响应式、主题 tokens、登录态和首次初始化流程。
- Manifest Page ID 与前端动态 import entries 的双向一致性检查；菜单顺序由服务端按 `Order` 裁决；权限码由 Manifest 统一入库。
- 公共组件：PageHeader、DataTable、Form、FilterBar、Modal、Drawer、Tabs、Empty、Pagination、Notify。
- 页面：登录、首次初始化、Dashboard、用户、角色、审计、配置（只读）、个人资料。
- 浏览器内测试面、组件测试、架构测试、真实浏览器验收记录。
- 生产 `go:embed` 和开发磁盘模式贯通。

### 验收

- 完成初始化 → 登录 → 仪表盘 → 用户/角色/配置查看全流程；配置写入不在 v0.x 承诺范围。
- 未授权菜单不展示，直接访问后端 API 仍被拒绝。
- 网络面板证明仅加载当前页面模块；切换页面后才加载对应 ESM。
- 页面卸载释放监听器、计时器和请求；键盘和焦点交互可用。
- 没有裸 fetch、前端硬编码菜单、全局 DOM 直接操作和非统一提示。
- 浏览器测试全绿并通过人工实看。

### 不做

任务中心、调度、文件管理、复杂报表和图表编辑器。

## 7. P4：运营能力（v0.2）

### 目标

补齐中后台长期运行所需的后台任务、调度、文件和系统诊断能力。

### 交付

- Task Center：在当前纯内存 `infra/tasks.Center` 上设计并实现持久化仓储/恢复协议，涵盖进度、任务日志、取消、重试、重启接管和保留期清理；先审计现有任务状态和 ID 契约，不复制建设第二套中心。
- Scheduler：复用已存在的 `infra/scheduler` 和 `Store` 接口；补齐持久化 Store、故障恢复与并发边界。它只做触发与记账，业务长任务仍由 Task Center 执行。
- Storage：本地文件驱动、原子写入、对象元数据、鉴权下载和清理。
- Application Log 查询策略、Access Log 诊断、Audit Log 查询；不得混淆四种日志语义。
- 系统页面：任务、调度、日志、审计、文件、系统信息/依赖状态。
- 清理任务和保留策略。

### 验收

- 任务可查进度/日志/状态，可取消；进程重启后运行中任务被收口。
- Scheduler 只提交任务；重复触发、上轮未结束和时钟边界有确定行为。
- 文件上传/下载/删除有类型、大小、路径和权限测试。
- 日志查询具备分页/时间范围上限，审计记录不可由普通用户修改。
- 关闭时任务、scheduler、storage、logger 资源按序退出。

### 不做

分布式调度、集群抢占、对象存储厂商强依赖和复杂可观测平台。

## 8. P5：CLI 与模块生态（v0.5）

### 目标

把快速创建项目和模块变成可重复、可审计的工程流程，并建立最小 Provider/Adapter 机制。

### 交付

- CLI：`new`、`module add`、`dev`、`build`、`doctor`、`version`。
- `templates/app` 最小业务项目模板；唯一的 `examples/biz` 展示业务 CRUD、结构同步、页面和扩展方式。
- 模块生成器产出 Go 目录、Manifest、SQL、WebUI ESM、测试和文档骨架；生成物必须可读可编辑。
- Provider/Adapter 接入契约：存储、数据库驱动、认证源、通知等按真实需求接入；显式装配、版本兼容检查。
- 模块契约测试、依赖树报告和资源清单校验。
- 第三方模块开发规范与最小示例。

### 验收

- 干净目录 `easyadmin new demo` 后能构建、启动和登录。
- `module add orders` 后模块可编译、登记 API/菜单/权限/页面，测试骨架可执行。
- 生成物不存在不可解释的模板变量或运行期隐藏生成步骤。
- 旧版本生成的项目升级后能构建、启动，核心结构已同步且业务结构脚本未被改写。
- Provider 缺失、重复或版本不兼容能明确失败。
- 不依赖 Go `.so` 插件或远程代码下载。

### 不做

在线模块市场、低代码生成、跨进程插件协议、多实例调度。

## 9. P6：稳定与正式发行（v1.0）

### 目标

把框架从“可以使用”推进到“可以被多个真实业务项目长期依赖”。

### 交付

- 公开包/API/Module/Provider 契约清单和语义化版本策略。
- API 向下兼容测试：固定旧版客户端请求/响应 fixture，禁止字段删除、类型变化和语义漂移。
- 数据库方言、结构同步、数据迁移、备份恢复和升级兼容测试矩阵。
- 性能基准：HTTP/中间件、数据访问、任务吞吐、首屏与页面切换。
- 安全基线：会话、CSRF、登录限流、密码策略、响应头、上传、依赖漏洞和敏感数据审查。
- 依赖升级、弃用、数据迁移、回滚和故障排查文档。
- Linux/macOS/Windows 等目标平台发行验证，版本/构建信息和 SBOM/许可证清单（按实际交付要求）。
- 至少两个真实业务项目试用并将问题回灌。

### 验收

- 升级指南从旧版本到 v1.0 可按步骤复现；公开契约有兼容策略。
- 关键性能与安全检查有可重复数据和测试。
- 文档示例在干净环境执行通过。
- 真实项目不需要修改 EasyAdmin 内核源码即可接入业务模块。
- 未支持能力、单实例限制和数据库支持级别清楚公开。

### 不做

不为版本号堆砌无真实需求的子系统；不把未来多实例和多租户写成当前能力。

## 10. 跨期质量闸门

| 闸门 | 统一要求 |
|---|---|
| 可构建 | gofmt、go test、go vet；适用时 race |
| 可启动 | 默认配置和无外部服务（除明确可选项）可启动 |
| 可回归 | 新功能有测试，缺陷有回归用例 |
| 可解释 | 新抽象和架构变化有决策记录 |
| 可观测 | 错误有 request_id、结构化日志和状态 |
| 可交付 | API/数据/配置/UI/文档同步，浏览器实际验收 |
| 可回退 | 有结构变更/数据迁移风险说明、关闭策略和恢复步骤 |

## 11. 关键风险

- **过度设计**：只把内置后台和至少两个真实项目确实需要的能力纳入公共层。
- **魔法回潮**：架构测试禁止隐式装配、反射扫描和全局 Service Locator。
- **零构建复杂度**：用明确的页面生命周期、JSDoc、浏览器测试控制；若不够用，先证明问题再评审可选工具。
- **配置双真相**：来源与持久化类型明确；不把 `.env` 写回当作所有部署环境通用方案。
- **easy 库误判**：P1 必须核实真实版本源码、测试和运行语义。
- **多实例误承诺**：文档和诊断明确单实例边界。
