# EasyAdmin 总体架构设计

> 状态：综合设计建议，待评审确认。本文描述长期架构和契约边界；文件级施工安排在 `docs/plan/<项目>_IMPL_PLAN.md`，执行期 STEP 放入 `docs/plan/<项目>/`。

## 1. 目标与非目标

### 1.1 目标

- 新业务项目从空目录到可登录管理后台，路径尽可能短。
- 业务项目主要编写领域模型、业务规则、应用服务和业务页面，不重复建设基础设施。
- easy 系列独立演进，EasyAdmin 通过适配层消费其能力。
- 默认单机、单实例、SQLite、单二进制可运行；其他驱动和 Provider 按需启用并经过认证。
- 代码透明：装配处能看懂系统由什么组成，模块目录能看懂其提供什么，错误和生命周期可追踪。

### 1.2 非目标

不做通用 ORM/Active Record、微服务治理、RPC/服务网格、低代码平台；v1.0 不承诺多实例任务调度和多租户 SaaS；不把 RockSys 的代理/WAF 产品能力带进来。

### 1.3 技术基线

| 领域 | 设计基线 | 备注 |
|---|---|---|
| HTTP 语义 | 标准 `net/http` Handler | easyserver 的接入由适配层负责，先核实真实能力 |
| 配置 | easyconf + EasyAdmin 配置注册门面 | 不重复实现配置底层 |
| 数据 | easydb + SQL-first | 驱动支持矩阵以实测为准 |
| 日志 | 统一结构化 Logger 门面 | 优先兼容 `log/slog` 语义，底层适配 easyserver/log 能力 |
| 前端 | 原生 ES Module + CSS | 默认无 Node/npm 构建和运行依赖 |
| 数据库 | SQLite 默认；PostgreSQL/MySQL 作为目标驱动 | 每个方言必须跑结构同步和查询集成测试 |
| 密码 | 成熟密码哈希实现 | 参数、成本和升级策略需安全评审 |
| ORM | 不引入 | SQL 可见、可审计、可优化 |

Go 最低版本、easy 系列版本、驱动版本和第三方依赖清单在 P0/P1 根据真实源码、兼容性和安全状态冻结，不在未验证时把文档中的候选版本写成既成事实。

## 2. 核心原则

1. **以简驭繁**：最小默认路径完整可用，高级能力按需装配。
2. **显式优先**：构造函数注入、显式注册、显式错误、显式生命周期。
3. **统一入口**：同类能力只有一种受支持用法；内部仍按职责分包。
4. **各司其职**：easy 库、kernel、infra、apps、WebUI 互不越权。
5. **透明可观测**：故障不能静默，降级必须有边界、状态和日志。
6. **按需加载**：编译、启动装配、页面路由和重组件四层分别控制。
7. **先证据后结论**：底层库行为以实际源码、测试和适配验证为准。

## 3. 分层与依赖方向

```text
                    cmd/easyadmin（唯一组合根）
                /          |          |           \
             kernel     infra    apps      webui assets
               |           |          |               |
        仅标准库/契约     adapters   依赖 kernel +      HTTP API
                           |        infra 公共包
                       easyconf / easydb / easyserver
```

这是 Go import 依赖规则，不是运行时调用顺序：

- `cmd` 可以同时导入 kernel、infra 和具体模块，是唯一装配处。
- `kernel` 只负责 App、Module 契约、注册表、依赖校验和生命周期；不得依赖具体 `infra/db`、`infra/logx` 或某个 HTTP Server。
- `infra/*` 是基础设施唯一入口，内部适配 easy 系列和标准库；不得依赖业务模块。
- `apps/*` 依赖 kernel 的公开模块契约和 infra 的公开服务，不直接依赖 easy 系列底层 API。
- 模块之间不直接 import。优先通过构造函数注入消费方定义的窄接口，由 `cmd` 组合根显式接线；不把字符串键 Service Locator 当作常规调用方式。
- `webui` 只通过同源 `/api/` 契约交互，不知道 Go 包、数据库和私有配置。
- easy 系列不依赖 EasyAdmin，不接收框架业务逻辑。

`kernel` 不持有 infra 的具体实现。组合根负责将 `infra` 服务和模块构造函数组装为一个 App 实例。这样内核可独立测试，底层服务可替换，模块依赖关系可见。

业务项目通过 `go.mod` 依赖版本化 EasyAdmin，只 import `kernel`、`infra/*`、内置 `apps` 的公开构造函数和 `webui` 契约；不把框架代码复制进业务仓库。核心结构脚本、业务结构脚本、核心配置、业务配置和前端资源分别管理，具体机制见 `docs/SCAFFOLD_AND_UPGRADE.md`。

## 4. easy 系列适配边界

| 地基库 | EasyAdmin 适配职责 | 对上暴露 |
|---|---|---|
| `easyserver` | Server 启停、路由挂载、请求上下文转换、超时与优雅关闭 | 标准 `net/http` Handler 语义和 Server 生命周期 |
| `easyconf` | 配置项注册、默认值、取值、Watch、来源信息 | 类型化 Config Catalog、只读快照和变更事件 |
| `easydb` | 连接、事务、扫描、错误和方言接入 | 命名 DataSource、查询/执行/事务门面 |
| `easyserver/log` | 结构化日志写入与生命周期 | 统一 Logger 门面 |

适配层必须有实际价值：隔离底层差异、统一生命周期/错误/上下文，或提供测试替身。禁止给每个底层函数做无行为价值的同名包装。

已知边界：`lib/` 已克隆 easyconf、easydb、easyserver 最新源码，但源码存在不等于底层语义已认证。P1 必须核实 Handler/Context/Shutdown、配置优先级/Watch 并发、DB 事务/扫描/驱动支持、日志并发/Flush 等行为，并用锁定提交跑测试。

## 5. 运行内核与模块系统

### 5.1 App

`App` 是单个应用实例的生命周期所有者。它协调配置加载、模块登记、资源启动、健康状态和停机，不成为全局容器。

- `New` 只建立对象和校验静态选项，不监听端口、不启动后台 goroutine。
- `Run(ctx)` 执行启动序列并运行服务。
- App 拥有的资源必须登记关闭动作，停机使用统一 deadline。
- 测试可以创建多个独立 App 实例；生产默认运行一个。

### 5.2 Module 与 Manifest

概念接口（不是最终冻结的函数签名）：

```go
type Module interface {
    ID() string
    Manifest() Manifest
    Declare(ConfigRegistrar) error // 配置加载前：只声明配置元数据
    Register(Registrar) error      // 配置就绪后：登记运行资源
}

type Lifecycle interface {
    Start(context.Context) error
    Stop(context.Context) error
}
```

`Manifest` 至少声明：稳定 ID、版本、说明、显式依赖、默认启用状态、菜单、页面标识、权限码、结构脚本资源和能力元信息。Registrar 由框架契约定义，实际实现由组合根提供；模块不能直接触碰底层 Server 或 DB。

### 5.3 两阶段声明和启动序列

```text
cmd 显式 Use 模块
    ↓
收集所有模块 Manifest，检查 ID 和静态冲突
    ↓
Declare：所有已编译模块声明配置项（不访问运行期资源）
    ↓
配置加载、来源解析、类型/跨项校验
    ↓
按启用状态和依赖关系构建模块图
    ↓
Register：只为启用模块注册路由/菜单/权限/服务/任务类型
    ↓
结构同步器按声明式清单幂等补齐缺失表和索引（Register 不直接执行 DDL）
    ↓
Start：按拓扑顺序启动模块资源
    ↓
HTTP 服务就绪
    ↓
Stop：按逆拓扑顺序停模块，再关任务、数据源、日志等资源
```

关键规则：

- `Declare` 对所有被编译并显式装配的模块执行，确保关闭模块的配置元数据仍可被识别；不得做 IO 或启动 goroutine。
- `Register` 只对启用模块执行。禁用模块不注册路由、菜单、任务和运行资源。
- 启用模块所依赖的模块必须存在且启用；缺失依赖、依赖环、重复 ID、路由/菜单/权限冲突在监听前失败。
- 禁用是启动期装配决策，不承诺运行中动态热插拔；动态启停是未来独立设计。
- `Register` 只登记模块结构清单，不在注册过程中执行 DDL。
- Start 失败必须记录状态并清理已经启动的依赖资源；Stop 逆序执行且有超时。

### 5.4 跨模块协作

默认通过构造函数注入接口：消费者定义最小接口，提供者实现，`cmd` 负责装配。需要事件时使用明确事件类型和同步/异步语义。只有在模块可选性确实要求运行期发现时，才考虑受限 Provider Registry；必须类型化、有冲突检查，且不得隐藏依赖来源。

## 6. 四层按需加载

| 层次 | 手段 | 规则 |
|---|---|---|
| 编译期 | 组合根只导入项目需要的模块和驱动 | 未导入模块不进入业务项目产物 |
| 启动期 | 显式模块清单 + 启用配置 | 禁用模块不挂载路由和后台资源 |
| 路由期 | 浏览器原生 `import()` | 首屏只加载当前页面模块 |
| 组件期 | 页面内动态导入图表/编辑器等 | 重型依赖不进入首屏 |

不把“按需加载”解释为运行期下载任意 Go `.so`。首期扩展采用编译期 Go 包 + 显式装配。

## 7. HTTP 与 API 契约

- 业务 HTTP handler 使用标准 `net/http` 语义；easyserver 只在适配层负责监听/挂载。
- API 前缀统一 `/api/`；未命中的 `/api/` 路由不能回退到前端 `index.html`。
- 成功响应 `{ok:true,data,meta}`；失败 `{ok:false,error,meta}`；`meta.request_id` 是唯一 Request ID 位置。
- 400 表示请求格式、参数结构、未知字段或类型转换错误；413 表示请求体或上传内容超过大小限制；422 表示请求成功绑定后的字段及跨字段输入校验失败，可定位的字段错误按 `API.md` 返回 `error.details.fields`；409 表示与已存在数据或资源当前状态冲突，包括不可修改配置项和当前不支持重试的任务；401 未认证；403 已认证但无权限或 CSRF 失败；404 目标资源不存在；429 限流；500 未预期错误；503 依赖不可用。
- 路由、权限码、菜单和页面标识由 Manifest/Registrar 显式声明；前端菜单由服务端按当前用户权限过滤。
- Manifest Page ID 与前端 `router.registerEntries` 注册的映射是一对一契约（双向一致）；前端入口路径需要静态映射，架构测试校验完整性，不能声称前端代码路径由 Go 运行时自动发现。

推荐中间件顺序（最终顺序必须用集成测试固定）：

```text
RequestID（最外层）
  → Recovery
  → SecurityHeaders
  → AccessLog（记录完整请求生命周期）
  → CORS / OPTIONS（显式配置）
  → BodyLimit
  → Session Authentication
  → CSRF（写操作）
  → Route Permission
  → Handler
  → Unified Response / Error Mapping
```

健康探针、静态资源、登录和初始化接口的豁免规则必须显式列出。流式响应、上传、下载需要独立限制和访问日志完成语义。

## 8. 配置体系

配置只有一个逻辑注册中心。v0.x 只实现启动配置（Bootstrap Config）：

- **Bootstrap Config**：监听地址、主 DSN、日志、数据目录、密钥引用等进程启动配置，由 easyconf 适配层负责加载和来源优先级。
- **Runtime Settings**：作为后续扩展点保留，v0.x 不实现，不提供数据库覆盖启动配置的隐式入口。真正落地时须同时补持久化表、权限、审计、版本冲突和测试。

配置项必须显式登记类型、默认值、说明、归属模块、敏感标记、是否必填、热更类别和验证规则。`Declare` 阶段登记，配置加载后只读类型化读取。

热更类别：`hot`（可安全生效）、`restart`（需重启）、`immutable`（运行期不可改）。热更应先校验再发布不可变快照；无法安全回滚的项目标为 restart。配置持久化必须区分文件、环境变量和数据库来源；环境变量覆盖 `.env` 时，写 `.env` 不等于修改了有效值。管理 UI 必须展示来源/重启要求，不允许对部署托管字段作误导性承诺。

详细规则见 `CONFIGURATION_DESIGN.md`。

## 9. 数据访问与结构同步

- `infra/db` 是唯一数据库入口；业务代码不得自行 `sql.Open` 或暴露连接池。
- SQL-first：表结构、结构脚本和查询放 `.sql` 文件；参数绑定；动态排序/列名白名单校验；不引入 ORM。
- 核心 SQL 放 `sql/{sqlite,mysql,postgres}/`；模块 SQL 随模块放在模块目录。
- 编译期 `go:embed`，可选运行期外挂目录覆盖；外挂优先必须校验路径与文件来源，内嵌资源兜底。
- 开发期使用声明式结构同步：启动时按 `TableSpec` 清单幂等补齐缺失表和索引，`DiffSchema` 只做只读差异预览；不自动删列、改列、改类型或重命名。详见 D20。
- SQLite 是默认首发数据库；PostgreSQL/MySQL 只有在驱动、结构同步、事务、类型映射和查询集成矩阵通过后，才列为正式支持。
- 默认使用 `int64` 主键并与数据字典/API 一致；任务编号等跨系统标识可采用独立字符串 ID，不混用。

## 10. 日志、审计与可观测

日志类别分离：

- Application Log：程序运行、错误、依赖故障。
- Access Log：请求 ID、路由、状态、延迟、用户和来源。
- Audit Log：操作者、动作、资源、结果和脱敏变更摘要，独立持久化。
- Task Log：任务阶段、进度、重试与执行结果，关联 task_id。

应用日志统一结构化字段和脱敏；审计失败策略按操作风险声明；指标不得使用 request_id/user_id 等高基数标签。健康探针区分存活和就绪。日志中心不能假设任意日志文本都已经入库；查询能力需与具体输出/索引方案一致。

详细规则见 `LOGGING_DESIGN.md`。

## 11. 身份、权限与安全

- 默认本地账号 + 服务端会话 + HttpOnly/SameSite Cookie；写操作有 CSRF。
- 默认 RBAC：用户、角色、权限码；后端路由强制授权，菜单过滤只是 UI 体验。
- 禁用用户立即撤销会话；权限更新在后续请求生效；超级管理员不可被误删/禁用到零。
- 初始管理员仅在未初始化时创建；非回环监听必须使用显式部署口令或可信初始化流程，不给默认弱口令。
- 所有输入服务端校验；输出上下文转义；文件上传校验大小/类型/路径；敏感数据不进响应、日志和审计详情。

## 12. 任务、调度和存储

- 超过一次请求合理时长的工作走 Task Center；handler 不得直接创建无主 goroutine。
- Task 持久化状态、进度、日志、取消和有条件重试；重启遗留运行任务必须收口。
- Scheduler 只负责扫描到期和提交 Task，不直接运行长任务；单实例模式下上轮未结束时按策略跳过记账，不堆积。
- Storage 抽象最小化，首期仅保证本地存储；写入采用临时文件、校验、原子替换；下载必须经鉴权路由。

## 13. WebUI

采用用户提供版本的原生 ESM + 零构建基线：不将 Node/npm/Vite/Webpack 或 Vue/React 作为运行依赖。页面模块用 `mount(ctx)`/`unmount()`；全局布局唯一所有者；服务端 Manifest 提供菜单和页面标识；路由动态导入；统一 API、Notify、Theme、Store 和组件契约。详细设计见 `FRONTEND.md`。

为降低无类型前端的维护风险，采用 JSDoc typedef、ESLint/静态扫描（工具链如需 Node 则作为可选开发辅助，不能作为运行必需）、浏览器内测试和架构测试；核心发布链应仍可仅依赖 Go 和浏览器完成。

## 14. 单实例边界

v0.x/v1.0 第一阶段明确单实例优先。SQLite、进程内调度、任务执行和本地文件存储不宣称多实例安全。未来多实例必须整体设计共享会话、任务租约/抢占、调度选主、共享存储和结构同步锁，不可只加 Redis 或进程锁冒充高可用。

## 15. 质量闸门

每期必须满足：可构建、可启动、可回归、可解释、可观测、文档同步。架构测试必须能对故意违规的依赖、裸数据库入口、裸 fetch、重复页面 ID 和不一致 Manifest 报错。前端必须浏览器实测，不以截图代替功能测试，也不以单测代替真实操作。
